# Демо-сайты для холодных обращений

Генератор статических демо-сайтов для автосервисов, шиномонтажей, ремонта компьютеров
и салонов красоты + публикация на GitHub Pages.

**Схема адресов — «а»: один репозиторий, папка на клиента.**
`https://<логин>.github.io/demo/motor-plus/` — без своего домена, без DNS, без поддоменов.

## Что где лежит

```
clients/motor-plus.json      данные клиента (единственное, что вы правите руками)
_templates/site/             шаблон мастерской: index.html + config.js + app.js + шрифты + фото
_templates/beauty/           шаблон салона красоты: index.html + config.js + js/main.js + фото
new_demo.py                  сборка, публикация, удаление
.github/workflows/pages.yml  сборка на стороне GitHub (рекомендуемый режим)
functions/lead/handler.py    серверная функция приёма заявок (Yandex Cloud Functions)
docs/                        собранные сайты для режима «из ветки»
dist/                        локальные сборки (в .gitignore)
```

Шаблон — обычный HTML с маркерами `<!--PRICES-->`, `<!--REVIEWS-->`, `<!--FAQ-->`, `<!--CREDIT-->`.
Название, телефон, адрес и часы уезжают в `data.js`, который читает `config.js`, —
поэтому в разметку их вписывать не нужно.

## Быстрый старт

```powershell
python new_demo.py new kuzov-54           # создать заготовку JSON для нового клиента
python new_demo.py build motor-plus         # собрать в dist/motor-plus и посмотреть локально
python new_demo.py publish motor-plus       # закоммитить и запушить
python new_demo.py list                     # что есть
python new_demo.py delete motor-plus --yes  # удалить демо
python new_demo.py build-all                # собрать всё (то же запускает CI)
```

Локальный просмотр: `start dist\motor-plus\index.html` (Windows), `open dist/motor-plus/index.html` (macOS).

## Данные клиента

`clients/<slug>.json`, slug — латиница в нижнем регистре и дефис, 2–41 символ: `motor-plus`.

| Поле | Обязательное | Что это |
|---|---|---|
| `slug` | да | совпадает с именем файла |
| `name` | да | «МОТОР ПЛЮС» |
| `phone` | да | любой формат, скрипт приведёт к `tel:+7...` |
| `template` | нет | `"site"` — мастерская, `"beauty"` — салон красоты |
| `niche` | нет | если `template` не задан: `beauty` → шаблон салона, остальное → мастерская |
| `district` | нет | район/город для заголовка |
| `address`, `hours` | нет | адрес и часы; часы OSM (`Mo-Su 10:00-21:00`) шаблон салона переводит в «ежедневно 10:00–21:00» |
| `rating`, `reviews_count` | нет | рейтинг и число отзывов (для шаблона салона — в шапке) |
| `email`, `telegram` | нет | контакты для шаблона салона; шаблон мастерской их не показывает |
| `prices` | нет | `[{"service": "...", "price": "от 2 500 ₽"}]`; нет — подставятся нейтральные |
| `reviews` | нет | `[{"text","author","car","source"}]`; нет — подставятся вымышленные |
| `faq` | нет | `[{"q","a"}]`; добавляются к пяти общим вопросам |
| `credit` | нет | атрибуция фото: `{"text","url"}` |
| `noindex` | нет | по умолчанию `true` |
| `live` | нет | `true` — убрать плашку «Демо» сверху (когда клиент согласился); в футере остаётся пометка «демо-версия» |
| `form_endpoint` | нет | URL функции приёма заявок; пусто — форма показывается, но при отправке пишет «это демо» и предлагает позвонить |
| `days` | нет | рабочие дни для записи, `[1,2,3,4,5,6]` (1 — понедельник, 7 — воскресенье) |
| `slots` | нет | время записи, `["9:00","10:00"]`; по умолчанию 9:00–18:00 |
| `domain` | для схемы «б» | ваш домен без поддомена: `example.ru` |

Каждый собранный сайт помечен как демо: сверху плашка «Демо — так мог бы выглядеть сайт «…»,
цены и отзывы пример», в футере — `демо · не для поиска`. Убирается полем `"live": true`.

### Какой шаблон достанется клиенту

Сборщик смотрит на поле `template`, иначе на `niche`, иначе на префикс слага
(так узнаются файлы, сохранённые до появления поля `niche`):

| Ниша | Шаблон | Где данные |
|---|---|---|
| `beauty` | `_templates/beauty` — тёмный сайт салона с галереей и записью | `config.js` |
| `auto_repair`, `tyres`, `computer` | `_templates/site` — сайт мастерской | `index.html` + `data.js` |

Шаблон салона не выдумывает данные: цены, мастеров, отзывы и «о салоне» он покажет
только если их передали в JSON. Без них эти секции просто не выводятся, а на сайте
остаются шапка, галерея, запись и контакты. Фотографии в шаблоне — пример оформления,
это написано в подвале демо.

Проверка после правки — `python new_demo.py build motor-plus`. Скрипт падает с понятным
текстом, если JSON битый, slug не тот или обязательное поле пустое.

## Добавить второй сайт и следующие

Один клиент = один JSON. Ничего копировать руками не нужно:

```powershell
python new_demo.py new kuzov-54        # создать заготовку clients/kuzov-54.json
# заполнить name, phone, district, address, hours, prices, reviews
python new_demo.py publish kuzov-54    # собрать, закоммитить, запушить
```

Push в `clients/*.json` запускает workflow — он пересобирает **все** демо сразу,
а не только новое. Старые сайты при этом не меняются, если их JSON не трогали.

Адрес нового демо: `https://<логин>.github.io/<репозиторий>/kuzov-54/`.
Общий список всех демо — на главной: `https://<логин>.github.io/<репозиторий>/`.

Проверка, что прошло: `python new_demo.py list` показывает оба клиента как «собран»;
в **Actions** появился запуск на вашем коммите; через 1-2 минуты открывается ссылка.

Проверить локально до пуша: `python new_demo.py build kuzov-54` затем
`start dist\kuzov-54\index.html`.

Удаление: `python new_demo.py delete kuzov-54 --yes` — убирает JSON, пересобирает
сайт и общий список. Если один JSON битый, `build-all` соберёт остальные и назовёт
все проблемные файлы, но деплой не запустится, пока ошибка не исправлена.

### Сколько демо помещается

Все сайты живут в одном репозитории и одном деплое. Лимиты GitHub Pages считаются
на весь сайт, а не на папку: рекомендуемый размер репозитория-источника — 1 ГБ,
опубликованный сайт — до 1 ГБ, трафик — soft-лимит 100 ГБ/мес, таймаут сборки
10 минут. Один демо весит ~1,4 МБ (в основном фото), значит запас огромный.
Другое дело — 10-минутный таймаут: `build-all` собирает все сайты заново,
и на нескольких сотнях клиентов это станет заметно. Практический порог —
десятки демо; дальше пора переходить на генератор с инкрементальной сборкой
или нормальный хостинг.

### Когда один репозиторий становится неудобен

Он публичный. Все JSON видны, вся история коммитов тоже. Пока это демо для
холодных писем — нормально (данные и так с открытых карточек). Но если клиент
согласился и сайт становится боевым, ему там не место: переносите на отдельный
репозиторий со своим доменом (схема «б») или на обычный хостинг.

## Режимы публикации

**Режим 1 — GitHub Actions (рекомендуется).** В git лежит только `clients/*.json`.
Настройка один раз: **Settings → Pages → Source: GitHub Actions**. Дальше
`python new_demo.py publish motor-plus` коммитит один JSON, сайт собирает workflow.

**Режим 2 — из ветки.** Сгенерированные файлы лежат в `docs/`, Pages отдаёт папку `/docs`.
Удалите `.github/workflows/pages.yml` и в **Settings → Pages** выберите
*Deploy from a branch → main → /docs*. Ограничение: soft-лимит 10 сборок в час
(на режим с Actions не действует).

## Свой домен (схема «б»)

```powershell
python new_demo.py publish motor-plus --per-repo
```

Создаёт репозиторий `demo-motor-plus`, включает Pages и печатает DNS-запись.
Требует `winget install --id GitHub.cli` и перезапуска терминала.

1. **Сначала** домен в настройках Pages репозитория, **потом** DNS-запись у регистратора.
   Наоборот — дырка: поддомен успеет занять кто угодно.
2. DNS: `CNAME  motor-plus  →  <логин>.github.io` (без имени репозитория!).
3. Верификация домена в настройках аккаунта: TXT `_github-pages-challenge-<логин>.example.ru`.
4. **Settings → Pages → Enforce HTTPS** — после выпуска сертификата.
5. Не делайте wildcard `*.example.ru` — GitHub прямо не рекомендует.

Сроки: DNS 5–30 минут (до 24 часов), сертификат Let's Encrypt — от минут до суток.

```powershell
Resolve-DnsName motor-plus.example.ru -Type CNAME
Resolve-DnsName _github-pages-challenge-<логин>.example.ru -Type TXT
curl.exe -I https://motor-plus.example.ru
```

## Форма заявок

Токен бота нельзя держать в JS — его увидит любой, кто откроет исходники страницы.
Цепочка: страница → ваша serverless-функция → Telegram.

`functions/lead/handler.py` — обработчик для Yandex Cloud Functions (Python 3.12, точка входа `handler.handler`).

| Переменная | Значение |
|---|---|
| `TG_BOT_TOKEN` | токен бота от @BotFather |
| `TG_CHAT_ID` | ваш chat_id (написать боту, затем `api.telegram.org/bot<токен>/getUpdates`) |
| `ALLOWED_ORIGIN` | `https://<логин>.github.io` |
| `HOURLY_LIMIT` | необязательно, по умолчанию 20 |

Секреты задаются в консоли облака как переменные окружения функции — в репозиторий они не попадают.
Защита от спама: honeypot (поле `company`), проверка телефона, лимит по IP, проверка `Referer`,
плюс пауза 60 секунд на клиенте. Лимит в памяти процесса «мягкий»: для жёсткого нужен Redis
или встроенный rate-limit платформы.

Подключение: `"form_endpoint": "https://functions.yandexcloud.net/<id>"` в JSON клиента.

### Что в форме

| Поле | Зачем |
|---|---|
| телефон | обязательное, минимум 10 цифр; без него заявка не уходит |
| услуга | выпадающий список из `prices` (`service`), первым идёт «Не знаю, нужна диагностика» |
| дата, время | строятся в браузере на 14 дней вперёд по `days`/`slots`; прошедшие часы сегодня не предлагаются |
| имя, машина, «что беспокоит» | необязательные, уходят в Telegram |
| галочка согласия | обязательная, иначе заявка не отправляется |
| `company` | honeypot: скрыт от человека, заполнен — функция молча отвечает «ок» и ничего не шлёт |

Даты и время формирует `app.js` на клиенте — в собранном HTML их нет, поэтому статичный
файл не «протухает». День и часы в заявке — это пожелание клиента, а не бронь:
подтверждает всё равно сервис звонком. В Telegram приходит строка «Когда: вт, 18 ноя, 11:00».

## Приватность

На бесплатном тарифе репозиторий с Pages публичный: JSON клиента, адрес, телефон и история
коммитов видны всем. Кладите только то, что и так есть на карточке в Яндекс.Картах.
Удалённое демо остаётся в истории git — если данные чувствительные, чистите историю
(`git filter-repo`) или заводите под демо отдельный репозиторий.
